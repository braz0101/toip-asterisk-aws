Configurer les comptes SIP — pjsip.conf

Extensions 1001 et 1002 avec gestion NAT complète

▶
📌 C'est quoi PJSIP ? PJSIP est le module SIP moderne d'Asterisk. Il gère l'authentification des utilisateurs, la signalisation SIP et la correction NAT. Chaque utilisateur est défini par 3 objets : endpoint (capacités), auth (authentification), aor (adresse de contact).

Pourquoi les 3 options NAT sont obligatoires

OptionRôle
rtp_symmetric=yesRenvoie le RTP vers l'adresse source — corrige les mobiles derrière NAT
rewrite_contact=yesCorrige l'adresse de contact SIP envoyée par le téléphone
force_rport=yesForce l'utilisation du port source — corrige l'iPhone qui envoie son IP privée dans le SDP

Configuration complète — /etc/asterisk/pjsip.conf

bash
sudo rm /etc/asterisk/pjsip.conf
sudo nano /etc/asterisk/pjsip.conf
ini — /etc/asterisk/pjsip.conf — VERSION FINALE ✅
; ===== TRANSPORT UDP =====
[transport-udp]
type=transport
protocol=udp
bind=0.0.0.0:5060
external_media_address=TON_IP_PUBLIQUE_AWS
external_signaling_address=TON_IP_PUBLIQUE_AWS
local_net=172.31.0.0/16

; ===== MODÈLE COMMUN ENDPOINT =====
; IMPORTANT : pas de use_avpf ni force_avp (bloque la négociation audio)
; rtp_symmetric + rewrite_contact + force_rport = correction NAT obligatoire
[ep-base](!)
type=endpoint
context=internal
disallow=all
allow=ulaw
allow=alaw
allow=g722
allow=gsm
allow=h264
allow=vp8
dtmf_mode=rfc4733
media_encryption=no
direct_media=no
rtp_symmetric=yes
rewrite_contact=yes
force_rport=yes

; ===== MODÈLES AUTH ET AOR =====
[auth-base](!)
type=auth
auth_type=userpass

; IMPORTANT : le nom de l'AOR doit être identique au numéro (1001/1002)
; sinon Asterisk retourne "AOR '' not found"
[aor-base](!)
type=aor
max_contacts=2
remove_existing=yes
qualify_frequency=30

; ===== UTILISATEUR 1001 — ÉTUDIANT =====
[1001](ep-base)
auth=auth1001
aors=1001
callerid="Ibrahima Fall" <1001>

[auth1001](auth-base)
username=1001
password=

[1001](aor-base)

; ===== UTILISATEUR 1002 — PROFESSEUR =====
[1002](ep-base)
auth=auth1002
aors=1002
callerid="Mr Mbaye" <1002>

[auth1002](auth-base)
username=1002
password=

[1002](aor-base)
🔴 NE JAMAIS ajouter d'ACL dans pjsip.conf Une ACL dans pjsip.conf bloque TOUS les endpoints y compris tes propres téléphones. La sécurité contre les scanners est gérée uniquement par Fail2ban (étape 14).

ini — /etc/asterisk/extensions.conf — VERSION FINALE ✅
[general]
static=yes
writeprotect=no

[internal]

; --- Extension 1001 avec messagerie vocale ---
exten => 1001,1,NoOp(Appel vers 1001)
exten => 1001,2,Dial(PJSIP/1001,30)
exten => 1001,3,Set(CHANNEL(language)=fr)
exten => 1001,4,Voicemail(1001@default,u)

; --- Extension 1002 avec messagerie vocale ---
exten => 1002,1,NoOp(Appel vers 1002)

exten => 1002,3,Set(CHANNEL(language)=fr)
exten => 1002,4,Voicemail(1002@default,u)
exten => 1002,5,Hangup()

; --- Consulter sa boite vocale (*97) ---

exten => *97,2,VoiceMailMain(${CALLERID(num)}@default,,s)
exten => *97,3,Hangup()

; --- Test echo (9999) ---
exten => 9999,1,Answer()
exten => 9999,2,Playback(demo-echotest)
exten => 9999,3,Echo()
exten => 9999,4,Hangup()

; --- Conference (200) ---
exten => 200,1,NoOp(Conference 200)
exten => 200,2,ConfBridge(200)
exten => 200,3,Hangup()

; --- IVR Menu Principal (100) ---
exten => 100,1,NoOp(IVR Menu Principal)
exten => 100,2,Answer()
exten => 100,3,Set(CHANNEL(language)=fr)
exten => 100,4,Background(fr/bienvenue)
exten => 100,5,WaitExten(10)
exten => 100,6,Goto(ivr-timeout,s,1)

; Choix IVR : 1 = agent 1001
exten => 1,1,NoOp(IVR -> Agent 1001)
exten => 1,2,Dial(PJSIP/1001,30)
exten => 1,3,Hangup()

Conférence d'appel — confbridge.conf

Salle de conférence multi-participants — extension 200

▶
📌 C'est quoi ConfBridge ? ConfBridge est le module de conférence d'Asterisk. Il permet à plusieurs participants de se rejoindre dans une même salle audio/vidéo. Chaque participant compose le 200 et ils s'entendent tous. Supporte jusqu'à 10 participants simultanés.
⚠️ Ne pas supprimer le contenu existant Le fichier confbridge.conf contient des configurations système importantes. Ajoute uniquement les lignes ci-dessous à la FIN du fichier existant.
bash
# Ouvrir le fichier et aller à la fin avec Ctrl+End
sudo nano /etc/asterisk/confbridge.conf

Ajouter à la fin du fichier :

ini — À ajouter à la fin de confbridge.conf
[default_bridge]
type=bridge
max_members=10
record_conference=no
video_mode=follow_talker

[default_user]
type=user
announce_join_leave=yes
music_on_hold_when_empty=yes

Recharger et vérifier

bash
sudo asterisk -rx "module reload"

# Test : les 2 téléphones composent 200 → conférence établie
# Vérifier les participants pendant la conférence :
sudo asterisk -rx "confbridge list"

video_mode=follow_talker : la caméra affichée bascule automatiquement sur la personne qui parle — comportement naturel en visioconférence.

Centre d'appel — queues.conf

File d'attente avec agents 1001 et 1002 — stratégie round-robin

▶
📌 C'est quoi une Queue ? Une Queue (file d'attente) est un système qui met les appelants en attente et distribue leurs appels aux agents disponibles selon une stratégie définie. C'est le cœur d'un centre d'appel professionnel.
bash
sudo nano /etc/asterisk/queues.conf

Ajouter à la fin du fichier :

ini — À ajouter dans queues.conf
[general]
persistentmembers=yes
autofill=yes

[support]
strategy=rrmemory
timeout=30
retry=5
wrapuptime=5
announce-frequency=30
announce-holdtime=yes
announce-position=yes
music=default
member => PJSIP/1001,0,Agent 1 Ibrahima
member => PJSIP/1002,0,Agent 2 Mbaye

Explication des paramètres

ParamètreValeurRôle
strategyrrmemoryRound-robin memory — distribue en alternance, se souvient du dernier agent
timeout30Sonne chaque agent 30 secondes avant de passer au suivant
retry5Attend 5 secondes avant de réessayer si tous les agents sont occupés
wrapuptime5Laisse 5 secondes à l'agent après un appel avant d'en envoyer un autre
announce-holdtimeyesAnnonce au client combien de temps il va attendre
announce-positionyesAnnonce au client sa position dans la file
bash
sudo asterisk -rx "queue reload all"

# Vérifier la file d'attente
sudo asterisk -rx "queue show support"
✅ Résultatqueue show support affiche les 2 agents — Agent 1 Ibrahima (PJSIP/1001) et Agent 2 Mbaye (PJSIP/1002).

IVR avec Google Text-to-Speech

Message d'accueil voix naturelle française — extension 100

▶
📌 C'est quoi un IVR ? IVR (Interactive Voice Response) = Menu Vocal Interactif. C'est le système automatique qu'on entend quand on appelle une entreprise : "Pour le service commercial appuyez sur 1...". Il guide l'appelant vers le bon service sans intervention humaine.
📌 Pourquoi Google TTS ? Google Text-to-Speech (gTTS) génère une voix naturelle et claire en français, bien supérieure à espeak qui sonne robotique. On génère le message d'accueil en MP3 puis on le convertit au format WAV 8000Hz requis par Asterisk.

Étape 1 — Installation des outils

bash
# Installer pip et ffmpeg
sudo apt install -y python3-pip ffmpeg

# Installer la bibliothèque Google TTS
pip3 install gtts --break-system-packages

Étape 2 — Générer le message d'accueil

⚠️ Permissions Générer le MP3 dans le dossier home (/home/ubuntu/) puis le déplacer. Sinon erreur "Permission denied".
bash
# Aller dans le dossier home
cd ~

# Générer le message avec la voix Google (sans sudo)
python3 -c "
from gtts import gTTS
tts = gTTS('Bienvenue. Pour joindre lagent un, appuyez sur 1. Pour lagent deux, appuyez sur 2. Pour la file dattente, appuyez sur 0.', lang='fr')
tts.save('bienvenue_google.mp3')
"

# Vérifier que le fichier est créé
ls -lh ~/bienvenue_google.mp3

Étape 3 — Conversion en format Asterisk (8000Hz mono WAV)

bash
# Convertir MP3 vers WAV compatible Asterisk
sudo ffmpeg -i ~/bienvenue_google.mp3 \
  -ar 8000 -ac 1 -acodec pcm_s16le \
  /var/lib/asterisk/sounds/fr/bienvenue.wav -y

# Donner les bonnes permissions
sudo chmod 644 /var/lib/asterisk/sounds/fr/bienvenue.wav

# Vérifier le fichier
ls -lh /var/lib/asterisk/sounds/fr/bienvenue.wav

Étape 4 — Recharger et tester

bash
sudo asterisk -rx "dialplan reload"

Fonctionnement de l'IVR

  1. L'appelant compose le 100
  2. Asterisk répond et joue le message Google TTS en français
  3. L'appelant appuie sur une touche (DTMF) dans les 10 secondes
  4. 1 → appelle directement l'agent 1001
  5. 2 → appelle directement l'agent 1002
  6. 0 → entre dans la file d'attente Queue
  7. Si aucune touche → "Au revoir" → raccroche proprement
📌 C'est quoi DTMF ? DTMF (Dual Tone Multi-Frequency) = les sons générés quand on appuie sur les touches d'un téléphone. Chaque touche génère une combinaison de 2 fréquences sonores. Asterisk les détecte via dtmf_mode=rfc4733 configuré dans pjsip.conf.
✅ RésultatEn composant le 100 on entend la voix Google naturelle en français. Les touches 1, 2, 0 routent correctement vers les agents.

Analyse des protocoles avec Wireshark

Capturer et analyser les paquets SIP et RTP

▶
📌 Pourquoi Wireshark ? Wireshark permet de capturer et analyser en temps réel tous les paquets réseau. Pour la ToIP, on capture le trafic SIP (signalisation) et RTP (flux audio/vidéo) pour voir exactement ce qui se passe lors d'un appel.

Étape 1 — Installation

Télécharge depuis https://www.wireshark.org/download.html → Windows x64 Installer. Lance en tant qu'Administrateur.

Étape 2 — Choisir l'interface

Dans Wireshark, tu vois la liste des interfaces avec des courbes d'activité. Sélectionne celle qui bouge — généralement Wi-Fi ou Ethernet.

Étape 3 — Filtre de capture

Dans la barre de filtre en haut, tape exactement :

filtre wireshark
sip || rtp

Étape 4 — Lancer la capture

Clique sur le bouton ▶ (requin bleu) en haut à gauche.

Étape 5 — Faire un appel et observer les paquets SIP

Lance un appel depuis Linphone sans décrocher de l'autre côté :

Paquet SIPCe que ça signifie
REGISTERLinphone s'enregistre sur le serveur Asterisk
INVITEDébut de l'appel — contient le SDP avec les codecs et ports RTP
100 TryingAsterisk a reçu la demande
180 RingingLe téléphone de l'appelé sonne
200 OKL'appelé a décroché
ACKConfirmation de l'établissement de l'appel
BYEFin de l'appel (un des deux raccroche)

Étape 6 — Observer le RTP après décrochage

Décroche sur le 2ème téléphone → parle quelques secondes → raccroche. Des centaines de paquets RTP défilent = flux audio en temps réel encodé en G711 (ulaw/alaw).

Étape 7 — Écouter le contenu vocal des paquets RTP

  1. Menu Telephony → RTP → RTP Streams
  2. Tu vois 2 flux (un dans chaque sens de communication)
  3. Sélectionne un flux → clique Analyze
  4. Clique Play Streams 🔊
  5. Tu entends exactement la conversation enregistrée dans les paquets !
✅ Ce que ça démontreSIP gère la signalisation (établissement et fin d'appel). RTP transporte la voix en temps réel. La ToIP utilise exactement les mêmes protocoles réseau que les données web — mais avec des contraintes temps réel strictes.

Sécurisation — Fail2ban contre les scanners SIP

Protection automatique contre les attaques VoIP

▶
⚠️ Ton serveur est attaqué automatiquement Dès qu'un serveur SIP est exposé sur internet (port 5060), des robots automatiques (sipvicious, Censys) le scannent pour voler des lignes téléphoniques. Dans les logs Asterisk : messages "No matching endpoint found" = ces scanners.
📌 C'est quoi Fail2ban ? Fail2ban surveille les logs d'Asterisk. Si une IP dépasse 5 tentatives de connexion échouées en 10 minutes, elle est automatiquement bannie pendant 1 heure via une règle iptables.

Installation et configuration

bash
sudo apt install -y fail2ban
sudo nano /etc/fail2ban/jail.d/asterisk.conf
ini — /etc/fail2ban/jail.d/asterisk.conf
[asterisk]
enabled = true
port = 5060,5061
protocol = udp
filter = asterisk
logpath = /var/log/asterisk/messages
# Banni après 5 tentatives en 10 minutes pendant 1 heure
maxretry = 5
findtime = 600
bantime = 3600
bash
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# Voir les IPs bannies
sudo fail2ban-client status asterisk

# Débannir une IP si tu t'es bloqué toi-même
sudo fail2ban-client set asterisk unbanip TON_IP

Restriction SSH — Autoriser uniquement ton IP

Dans la console AWS → EC2 → Security Group → Règle SSH → Change la source de 0.0.0.0/0 vers "Mon adresse IP". Bloque toutes les tentatives SSH depuis internet.

💰 Gestion des coûts AWS Quand le serveur n'est pas utilisé → arrêter l'instance dans la console AWS EC2 (Actions → Instance → Arrêter). Ne pas supprimer. L'IP changera au redémarrage — mettre à jour pjsip.conf et Linphone.
